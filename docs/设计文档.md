## 0. 一句话定义

拍卷子 → agent 逐题估时建卷 → 开赛时以固定 seed 生成一条**有手感、有卡壳**的幽灵时间线 → 你打卡推进度，与幽灵赛跑 → 事件流经本地桥直存 `/var/minis/shared/`，agent 赛后直接读盘复盘。

## 2. 幽灵引擎：随机配速模型（本项目核心）

### 2.1 为什么"每题固定秒数"一眼假

真人的完题时间序列有四个统计特征，定死的时间表一个都没有：

1. **右偏**：多数题接近预估，少数题爆炸式超时（卡壳）→ 对数正态，不是均匀抖动
2. **手感漂移**：状态是连续变量——连着几题顺、连着几题卡，相邻题时间**相关**，不是独立噪声
3. **阶段结构**：开卷浏览、起步热身偏慢、60–75% 处疲劳 slump、末段冲刺
4. **离散事件**：卡壳跳过再回做、大题间检查回改、中途喝水发呆

### 2.2 模型（建卷/开赛时一次性生成整条时间线，seed 可复现）

```
T_i = pred_i × form_i × stage(i) × exp(σ·ε_i) × event_i   （最终以两遍生成整体缩放，submit 精确落在 pred×0.92~1.08，漂移幅度由 seed 决定）

form_i:  均值回归随机游走（OU 离散化）
         form_{i+1} = 1 + ρ·(form_i − 1) + η,  ρ=0.7, η~N(0,0.12), clamp[0.75, 1.45]
         → 产生持续若干题的"顺风段/逆风段"，相邻题自相关
ε_i:     N(0,1) 截断 ±2.5，σ=0.25 → 单题右偏噪声
stage(i): 热身（前2题 ×1.08）、低迷窗口（起点随 seed 在进度 40~65% 间漂移、宽 15~35%，×1.10）、其余 ×1.0
event_i: 事件层抽样（概率按题难度加权）：
         卡壳   易 3% / 中 12% / 难 20% → ×2.5–4，且 50% 标记"跳过"，完题时间推迟到末段
         回改   每个大题结束 p=40% → +30–90s 检查该大题
         停顿   全场 1–3 次（受题数钳制）→ +20–60s（喝水/发呆/削铅笔）
末段：   最后留总时长 3–8% 作为"检查阶段"，幽灵的"交卷时刻"≠ 最后一题写完时刻
开卷：   p=60% 先花 30–120s 浏览全卷（第 1 题开始时间推迟）
```

**参数随难度档缩放**：level ∈ {轻松 1.15 / 标准 1.0 / 挑战 0.85} 只乘 pred_sec（幽灵的整体用时预算），事件概率不随档位变化。注意方向：**level 乘的是幽灵的用时**——挑战档 ×0.85 = 幽灵快 15%（更难），轻松档 ×1.15 = 幽灵慢 15%（更易）。历史 session 的 level 字段按同一语义解释（旧 UI 标签曾是反的，2026-08-18 修正）。

### 2.3 为什么必须"赛前一次生成 + seed 存档"

- 页面端只是**按 wall-clock 线性扫描查表时间线**——冻结、杀后台、重开页面全部无损对齐
- 离线 fallback 天然成立（时间线内嵌 paper/session 配置，赛中零网络依赖）
- seed 存进 session，赛后可完整回放"幽灵这场比赛经历了什么"，复盘有戏剧性（"它在第 12 题卡了 4 分钟，你本来能拉开"）

### 2.4 显示层真实感：余光模式（默认开）

考场上你对别人的感知是**间接、陈旧、不精确的**：翻页声、余光一瞥。照搬：

- 幽灵位置**不是常显精确值**：开赛 20–60s 第一瞥，之后每 25–90s（随机间隔）"瞟一眼"才刷新，平时显示的是上次看到的旧位置（UI 标注"X 秒前瞥见"）。两个例外：幽灵交卷立即揭示（考场公开事件）；你做完/跳过一题时刷新一次（做完一题自然抬头看考场）
- ~~幽灵跨大题/翻页时播放翻纸声、被超时笔落声~~（未实现；翻页声曾上线，后按用户反馈删除）
- ~~"遥测模式"：精确常显 + 精确时间差~~（未实现）

### 2.5 赛中信息输出：ETA 与领先/落后（实现版）

**幽灵预计完卷（ETA）**——只在瞥见时更新，平时冻结（没见就没新估计）。公式 = **沉没成本 + 剩余工作量 × 已完工配速**：
- `pace = (最后一题完工时刻 + predTotal/3) / (已完成题预测和 + predTotal/3)`，收缩向计划配速 1.0
- 关键设计：**配速只由已完成的活证明**——卡壳/在制时间不进配速分子。局部卡壳 ≠ 全局降速：卡壳的代价以加法体现（卡一秒，交卷约推迟一秒），不再乘到全部剩余工作量上。（旧公式让卡壳窗内的时间流逝直接抬高配速，ETA 瞬时暴涨约 +30%，与"卡壳是暂时局部事件"的判断直觉相悖——2026-08-18 废除）
- 在制题进度优先按真实工作窗口折算（见下）；无窗口退回完工插值
- 幽灵写完全卷、进入末段检查（3–8% 时长）：显示"收尾检查中"，不谎报具体时刻
- 已交卷：冻结在实际交卷时刻

**幽灵位置标注（真实化）**：幽灵"真正在做的题"由引擎的工作窗口（work，含卡壳整段与补做回做段）推导，不再用"下一件完工的事"冒充"正在做的事"：
- 卡壳窗内标注真正卡住的题；在制时长超该题预估 2 倍时显示"卡在"——考场里你早注意到邻座停笔了，不算作弊信息
- 补做窗内题号与进度标记真的往回走（幽灵翻回卷子）
- browse/停顿/回改间隙没有工作窗口，退回完工顺序近似

**领先/落后**——与 ETA 不同，用幽灵全量时间线（含未瞥见段）：开卷考试式赛跑，这是可接受的设计差异（注释在代码里）。
- 你的进度 = 完成题数 + 在制题折算 `frac = min(0.9, 当前题累计投入 / (预估 × 1.3))`——**刻意悲观**：同速做题最多唱衰约 1/3 道题，交题时结算归还；超时折算封顶但 −t 按秒掉，卡题照样显示失血。"累计投入"含跳题前的第一段，暂停期不计时
- 进度插值到幽灵相邻完工时刻之间，得 `leadSec = 幽灵到达同进度的时刻 − t`
- **终点 = 幽灵交卷时刻 submit**（不是写完最后一题的 writeEnd）：胜负以交卷判定，末段检查时间必须算进对手的赛程，否则冲刺段会凭空多报几分钟落后
- 开卷头 10% 进度显示"蓄势"不报数（起步噪声太大）

**超预估提示**：当前题累计投入 > 2.5 × 该题预估（含档位）→ 提示"已超预估，考虑跳题"。

## 3. 赛中 subagent（二期目标，当前未实现）

> 现状：没有赛中 subagent——bridge 只有数据直存端点（health/list/latest/session/save），无触发器；幽灵时间线开赛一次生成、赛中不可调；复盘为赛后统一进行。本节是二期设计，先记下。

角色定位：**比赛分析师 + 配速模型维护者**，不是啦啦队。考场上没人说话，所以它也不该刷屏——输出克制。

- **做什么**：
  1. 实时盯你的事件流：异常停滞（单题 2.5× 预估）→ 页面角落一条系统提示"这题已超预估 2.5 倍，考场策略建议跳过"，你说听不听随你
  2. 判断你的本场状态因子（比预测快/慢多少），**赛后**写回个人校准系数库
  3. 赛后即时复盘（不用等你导出）：逐题偏差、转折点、下一份卷的难度档建议
- **调速规则（有度、且无声）**：允许赛中按你的实际速度微调幽灵剩余配速——**全场累计 ≤ ±10%、次数 ≤ 2 次**。**不做任何页面提示**（考场上没人告诉你对手加速了，这对做题的人是纯噪音）；调整只静默写入 session 日志，供赛后复盘。
- **实现**：bridge.py 收事件 → 触发器（停滞/过半/完赛）→ `minis-model-use` 调快速小模型 → 结果写入 session 目录 + 返回页面。延迟 5–15s 可接受。
- **fallback**：桥不可达 → 页面纯本地跑（时间线赛前已内嵌），事件攒 localStorage，下次桥上线自动补传；subagent 分析降级为赛后统一补做。**离线模式功能不残缺，只少实时分析。**

## 4. 架构（双模，已实测可行）

```
开卷（agent 在线）:  照片 → 逐题估时 → papers/<id>.json + 幽灵时间线(seed)
开赛（页面，双模）:  minis://shared/paper-race/app/index.html
   ├─ 在线: 事件 POST → 127.0.0.1:8756 bridge.py → 落盘 sessions/ + subagent 触发
   └─ 离线: localStorage 攒事件 → 桥恢复后自动补传（手动兜底：导出 JSON）
赛后（agent 在线）:  直接读 sessions/*.json 复盘（零拷贝）
```

目录（shared 是必要的：workspace 按 session 隔离，而数据和 app 必须跨 session 存活）：

```
/var/minis/shared/paper-race/
  app/            多文件前端（index.html / css / js / assets 翻页声）
  data/papers/    建卷 JSON（含幽灵时间线 seed 与参数）
  data/sessions/  比赛事件流 + subagent 分析结果
  data/profile/   个人校准系数库（学科×题型乘子）
  bridge/         bridge.py（存数据 + subagent 触发器）
  docs/           本文档 + 维护手册.md
```

卷子数据的建/改 = 用户在聊天里让 agent 直接写 `papers/*.json`（操作规程见 docs/维护手册.md），**页面不做导入 UI**。幽灵时间线不由 agent 预生成文件，由页面端按 pred_sec + seed（=开赛时刻的秒级时间戳，同日重赛不撞同一只幽灵）用内置引擎派生——paper JSON 只存题目与预估，保持极简。

## 5. 页面设计（重量级，四屏）

视觉语言：**深夜书房**。暗宣纸底 + 墨灰主文字 + 朱红（你，印章色）vs 青白半透明（幽灵，墨渍色）。标题衬线（Songti SC），数字等宽 tabular。少装饰，信息密度靠排版层级。

1. **卷库**：卷卡片（科目/题量/预测总时长/历史最佳战绩）+ 连胜印记 + "拍新卷"入口
2. **赛前**：题目地图（逐题预估秒数的等高条）、幽灵档位选择（轻松×1.15 / 标准×1.0 / 挑战×0.85——乘的是幽灵用时：倍数越大幽灵越慢）、已赛卷显示上次成绩、3-2-1 倒计时（点按=立即开卷）。防熄屏由 wakeLock 自动处理，无检查项 UI
3. **赛中**（核心，**横屏优先**——用户比赛时横放手机）：左列——已用时、卷轴赛道（朱红点 vs 青白拖尾幽灵）、余光状态行、当前题号与预估；右列——整面「✓ 写完这题」朱红大按钮（盲按设计：拇指自然落点）+ 角落「跳题」「暂停」。竖屏自动降级为上下布局。
4. **结算**：胜负印章（朱红"胜"/墨灰"负"）、总分对照（你的总时长 vs 幽灵）、逐题 预测/实际 对照条、幽灵事件回放摘要、正确率录入入口

关键工程细节：wakeLock 意图态串行链 + tick 巡检——比赛中丢锁（系统收回/release 竞态）2 秒内自动补回，**比赛中绝不灭屏**；切后台自动暂停（倒计时中切后台→开跑即自动暂停，秒表不空转）；打卡反馈 = 短音效 + 朱红闪（无震动 API），音效层与游戏逻辑完全隔离且永不哑巴（整体 try/catch：声音出任何故障不许吞打卡、不许挡开赛；死 context 立即重建；僵尸 context——活着但 resume 永不生效的 iOS 病灶——按"连续 3 次无声"判定弃掉重建，最多 3 次点按内自愈；每次手势用静音 buffer 预热解锁，回前台顺带重唤醒）；一切计时 wall-clock 驱动；页面冻结/重开后断点恢复：一律以暂停态醒来，时钟对齐存档最后事件时刻（死时间兜底）。恢复前校验存档与卷子兼容（题数/题号逐一吻合）——不兼容说明存档后卷子被改过，硬恢复会让事件流题号错配崩溃；此时**绝不静默删档**：存档挪入孤儿区（gp_orphan），卷库页挂出明示条让用户找 agent 尽可能修复，桥在线时自动备份到 data/profile/ 供 agent 取证（处理规程见维护手册"操作四"）。

## 6. 数据 schema（实现版）

papers/<id>.json 只存题目与预估，**不存幽灵**（幽灵由页面按 seed 开赛时派生；格式详见 docs/维护手册.md）。题号 n 从 1 连续 = 唯一内部键；可选 `label` = 卷面显示名（板块卷每板块从 1 重新编号时用，如 "一·3"），纯显示层、不进存档，无 label 的卷子行为与旧版逐字节一致。

sessions/<id>.json（id = s_ + 完赛时刻 UTC 紧凑时间戳）：

```jsonc
{
  "id": "s_20260817051414",
  "paper_id": "physics-summer-03",
  "level": 1.0,                    // 幽灵用时倍数：轻松1.15/标准1.0/挑战0.85
  "seed": 1787000000,              // 开赛时刻秒级时间戳；配合 level 可完整重放幽灵
  "started_at": "...ISO...",       // 注意：中断恢复后这是最初开赛时刻
  "events": [                      // 你的事件流；t=秒(暂停期冻结)，wall=墙钟ISO
    {"t": 0, "ev": "start", "wall": "..."},
    {"t": 41.2, "ev": "done", "q": 1, "wall": "..."}
    // ev ∈ start/done/skip/pause/auto_pause/resume/finish
  ],
  "ghost": {
    "submit": 3721.4,              // 交卷时刻（胜负判定线）
    "writeEnd": 3502.0,            // 写完最后一题时刻（交卷前还有 3–8% 检查期）
    "seedUsed": 1787000000,
    "notes": ["第 12 题卡壳", "停顿 43s"],        // 复盘可读摘要
    "doneList": [{"q": 1, "t": 96.3}]             // 全题完工时刻（含补做），按 t 升序
  },
  "result": {
    "your_total_sec": 3601, "ghost_submit_sec": 3721, "win": true,
    "per_q": [{"n": 1, "pred_sec": 75, "actual_sec": 62}]  // pred 已含档位倍数；该题有 label 时各项另附 "label" 快照（显示名，结算/导出用）
  }
}
```

页面 localStorage：`gp_active`（进行中比赛现场，断点恢复用）、`gp_pending`（桥离线时待补传的完整 session）、`gp_history`（卷库卡片战绩缓存）、`gp_last`（最近一场缓存）、`gp_results`（按卷的结果缓存）。

## 7. 风险修订

| 风险 | 对策（v2 新增） |
|---|---|
| 随机幽灵偶尔"运气太好/太差"不像话 | 生成后校验：总时长落在 [0.92, 1.08]×预测内，卡壳题数 1–3 个，超限重摇 seed |
| 余光模式信息太少焦虑 | 遥测模式随时可切；被超越有声音提示兜底 |
| 桥依赖 iSH 前台存活 | 离线模式零功能残缺（除实时分析）；补传机制 |
| 赛中 subagent 延迟/失败 | 提示全部可丢弃；失败静默降级 |

## 8. 路线图

- **v1**：随机幽灵引擎 + 四屏页面 + 离线模式 + 数据直存桥 + 赛后我读盘复盘
- **v2**：赛中 subagent 实时分析、个人校准系数自动回写、正确率录入
- **v3**：自己的历史幽灵回放（"和上周的你赛跑"）、自适应难度（明示版）、周报
