# 卷灵 GhostPace · Agent 维护手册

> 给任何接手的 agent：这个项目的主人是学生，用本系统和"幽灵"赛跑做卷子来提速。
> 你的职责 = **建卷、改卷、赛后复盘**。原则是简洁：数据落盘是本体，其他都是洒洒水。

## 目录

```
/var/minis/shared/paper-race/
  app/            前端（用户用浏览器打开 minis://shared/paper-race/app/index.html）
  data/papers/    卷子 JSON ← 你主要维护这里
  data/sessions/  比赛事件流（页面自动写入，你只读）
  data/profile/   个人校准系数 calibration.json（复盘后由你更新）+ active_orphan_*.json（孤儿存档备份）
  bridge/         本地桥（数据直存）
  design/ docs/   设计稿与文档
```

## 操作一：建新卷

用户在聊天里给你卷子照片或题目文本 → 你写 `data/papers/<id>.json`：

```jsonc
{
  "id": "math-summer-03",           // 科目-来源-序号，kebab-case
  "title": "数学暑假卷（三）· 函数与几何",
  "subject": "math",                // math/chinese/english/physics/chemistry/...
  "grade": "高二",                   // 学段，影响估时先验
  "total_points": 120,
  "created_at": "2026-08-09T21:00:00+08:00",
  "questions": [
    {
      "n": 1,                        // 题号，必须从 1 开始连续（唯一内部键，事件流/幽灵/存档全用它）
      "label": "二3",                 // 可选：卷面显示名。仅当卷面编号≠连续题号时才加——典型场景：按板块组卷、每板块内部从 1 重新编号的卷子，label 写"板块+题号"（如 "二3" / "A1"）。解答卷的 21(3) 这类仍按完整第 21 题整题录，不需要 label。大部分卷子不加此字段，显示自动回落题号
      "type": "choice",              // choice/multi/fill/solve/reading/cloze/writing/other（multi=多选）
      "points": 3,
      "stem": "函数单调性判断",        // ≤25字概括，结算页和复盘要用
      "difficulty": "easy",          // easy/mid/hard（按该学段中等生）
      "pred_sec": 75                 // 预测用时（秒）= 原始估时 × 校准系数
    }
  ]
}
```

**pred_sec 的算法**：先按题目本身估一个"该学段中等偏上学生"的秒数，再乘 `data/profile/calibration.json` 里对应的 学科×题型 系数（没有则用 `_default`）。校准系数不存在时全部按 1.0。

**建卷后必须自检**：题号连续；每题 pred_sec > 0；显示名（label ?? 题号）全卷不重复——两个板块的第 1 题都叫 "1" 就分不清了（这正是板块卷要加 label 的原因），label 也不许撞别的题号（如 label "5" vs 第 5 题）；漏题并题是头号错误源。**落盘前必须与用户核对基础信息**（科目/年级/题量结构/预测总时长），确认后才写文件。

**落盘收尾（必须三步）**：
1. `python3 bridge/build_papers_js.py` —— 重新生成 `app/papers.js`（页面离线靠它读卷）；它同时会校验题号连续性和 pred_sec（子资源缓存由页面引导自动破戳，无需管 index.html）
2. 若比赛期间需要数据直存/补传：`python3 bridge/bridge.py > /dev/null 2>&1 &` 启动本地桥（页面每 15s 自动探测，离线则暂存 localStorage 后补）
3. 给用户入口链接 `[开卷：<标题>](minis://shared/paper-race/app/index.html#/brief/<id>)`——点开直达该卷赛前页

**不需要你生成幽灵时间线**：页面端按 paper 里的 pred_sec + seed（=开赛时间戳，session 里存 seedUsed 可复盘回放）用内置随机引擎派生，参数已内置。你只管估准 pred_sec。

## 操作二：改卷

直接编辑对应 JSON（改题、改预估、改标题），保持 id 不变，然后更新 `updated_at`。删卷先问用户。

> ⚠️ **增删题/改题号**会让该卷进行中的比赛存档在下次打开时判为"不兼容"，转入孤儿存档（见操作四）——改卷时若用户可能有没赛完的，先问一句，改完提醒 ta 来找你修。只改预估/题干/标题/label（不动题的数量与编号）不影响存档兼容——label 纯显示层，从不进存档。

## 操作三：赛后复盘

1. 读 `data/sessions/` 最新文件（事件流：t=秒, ev=start/done/skip/pause/auto_pause/resume/finish, q=**内部题号 n**（不是 label）；暂停期间 t 冻结，pause 与 resume 的 t 相同）；向用户报题时若该卷有 label，按卷子把 n 映射成卷面显示名；
2. 逐题实际用时 = 该题作为"当前题"的区间累加：从它成为当前题（上一个 done/skip 事件）到下一个事件的时长归它；**跳题后补做的第二段也归该题**（页面 app.js 的 attributeTimes 就是这个算法）。skip→done 跨度大的是"卡壳题"；
3. 按 学科×题型 算 实际/预测 比值，样本 ≥5 的格子更新进 calibration.json（平滑：新=0.7旧+0.3新观测）；
4. 回复用户：总胜负、最大偏差题、卡壳题、是否"提速但正确率存疑"（若有正确率录入）。简洁，三五行说清。

```jsonc
// data/profile/calibration.json
{"_default": 1.0, "math": {"choice": 1.1, "solve": 1.25}, "updated_at": "..."}
```

## 操作四：处理孤儿存档（用户说"有场比赛恢复不了"）

进行中比赛存档（gp_active）与当前卷子对不上（卷子被增删过题、改过题号、或删了卷）时，页面**不会删档**：存档转入孤儿区，卷库页挂红条让用户来找你，桥在线时还会自动备份到 `data/profile/active_orphan_<卷id>_<startWall>.json`。你的职责是尽可能救回：

1. **取证**：优先读 `data/profile/active_orphan_*.json`（桥在线时必有备份）；存档结构同 gp_active：paper_id/level/seed/startWall/events/order/skipped/done。
2. **诊断**：对照 `data/papers/<paper_id>.json` 现状确认不兼容原因。常见两种：
   - **卷子被改过结构** → 用 `git -C data log -p papers/<paper_id>.json` 找回存档当时的版本；若存档 order 与旧版题号逐一吻合，把卷子恢复到该版（改卷前按保护规程先提交）。
   - **paper_id 指错卷**（历史事故同款）→ 用存档 order 的题数/题号特征在卷库里反查真实卷，修正后写回。
3. **修复主路径（改卷，不改存档）**：页面读的是设备 localStorage 里的孤儿存档，你改不到它——但通常不用改它。把卷子修回与存档兼容（多数是恢复到旧版结构）后**必须重跑 `python3 bridge/build_papers_js.py`**（页面加载的是 app/papers.js），然后让用户打开页面点孤儿条上的"再试恢复"即可原地复活。
4. **存档本身坏了（paper_id 指错等）**：桥备份或用户点"复制存档"发来的 JSON 是取证来源。这类通常救不回原赛——向用户说明后，按复盘口径把 events 整理成补录 session 写入 `data/sessions/`（提交信息注明补录与原因），再请用户点"弃档"。**绝不替用户删孤儿存档。**

## 赛中 subagent 调速规则（二期目标，当前未实现）

> 现状：幽灵时间线在开赛时一次性生成，赛中不可调；bridge 也没有调速/触发端点。本节是二期的设计约束，先记下。

二期允许赛中根据用户实际速度微调幽灵剩余配速，但硬边界：**全场累计调整幅度 ≤ ±10%，次数 ≤ 2 次**。**不做任何页面提示**（考场仿真：没人广播对手加速）——调整只静默写入 session 日志，供赛后复盘。超出边界 = 裁判作弊，绝不允许。

## 保护规程（数据仓 git——你只需要管这个）

`data/` 目录是独立的 git 仓库（代码仓归用户主 agent 管，与你无关，**你不许碰 data/ 以外的任何文件**）。规则：
- **改任何数据文件之前**：`git -C /var/minis/shared/paper-race/data add -A && git commit -m "before: <要做什么>"`
- **改完验证无误后**：再 commit 一次说明改了什么
- 比赛 session 落盘时桥会自动提交，不用你管
- 纯读操作（复盘、分析）不用提交
- 数据异常或改坏了：**不要自行修复，停手并在回复里向用户说明情况**（用户会找专人处理）
- sessions/ 只新增、不修改（补录类修正除外，需在提交信息里说明原因）、不删除

## 红线

- **只许动 data/ 里的文件**；app/、bridge/、docs/、design/ 都是代码仓，由用户的主 agent 维护，你一行都不许改
- 不删 sessions/ 历史数据
- 保持简洁：不要为了"功能完整"加用户没要的东西
