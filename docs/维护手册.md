# 卷灵 GhostPaper · Agent 维护手册

> 给任何接手的 agent：这个项目的主人是学生，用本系统和"幽灵"赛跑做卷子来提速。
> 你的职责 = **建卷、改卷、赛后复盘**。原则是简洁：数据落盘是本体，其他都是洒洒水。

## 目录

```
/var/minis/shared/paper-race/
  app/            前端（用户用浏览器打开 minis://shared/paper-race/app/index.html）
  data/papers/    卷子 JSON ← 你主要维护这里
  data/sessions/  比赛事件流（页面自动写入，你只读）
  data/profile/   个人校准系数 calibration.json（复盘后由你更新）
  bridge/         本地桥（数据直存 + subagent 触发）
  design/ docs/   设计稿与文档
```

## 操作一：建新卷

用户在聊天里给你卷子照片或题目文本 → 你写 `data/papers/<id>.json`：

```jsonc
{
  "id": "math-summer-03",           // 科目-来源-序号，kebab-case
  "title": "数学暑假卷（三）· 函数与几何",
  "subject": "math",                // math/chinese/english/physics/chemistry/...
  "grade": "高二",                   // 学段，影响估时先验
  "total_points": 120,
  "created_at": "2026-08-09T21:00:00+08:00",
  "questions": [
    {
      "n": 1,                        // 题号，必须从 1 开始连续
      "type": "choice",              // choice/fill/solve/reading/cloze/writing/other
      "points": 3,
      "stem": "函数单调性判断",        // ≤25字概括，结算页和复盘要用
      "difficulty": "easy",          // easy/mid/hard（按该学段中等生）
      "pred_sec": 75                 // 预测用时（秒）= 原始估时 × 校准系数
    }
  ]
}
```

**pred_sec 的算法**：先按题目本身估一个"该学段中等偏上学生"的秒数，再乘 `data/profile/calibration.json` 里对应的 学科×题型 系数（没有则用 `_default`）。校准系数不存在时全部按 1.0。

**建卷后必须自检**：题号连续；每题 pred_sec > 0；Σpred_sec 除以 60 告诉用户"预测总时长 X 分钟"请其确认；漏题并题是头号错误源。

**落盘收尾（必须两步）**：
1. `python3 bridge/build_papers_js.py` —— 重新生成 `app/papers.js`（页面离线靠它读卷）并自动打 WebView 缓存版本戳；它同时会校验题号连续性和 pred_sec
2. 若比赛期间需要数据直存/补传：`python3 bridge/bridge.py > /dev/null 2>&1 &` 启动本地桥（页面每 15s 自动探测，离线则暂存 localStorage 后补）

**不需要你生成幽灵时间线**：页面端按 paper 里的 pred_sec + seed（默认=比赛日期）用内置随机引擎派生，参数已内置。你只管估准 pred_sec。

## 操作二：改卷

直接编辑对应 JSON（改题、改预估、改标题），保持 id 不变，然后更新 `updated_at`。删卷先问用户。

## 操作三：赛后复盘

1. 读 `data/sessions/` 最新文件（事件流：t=秒, ev=start/done/skip/pause/resume/finish, q=题号）；
2. 逐题实际用时 = 相邻 done 事件差（扣 pause 区间）；skip→done 跨度标为"卡壳题"；
3. 按 学科×题型 算 实际/预测 比值，样本 ≥5 的格子更新进 calibration.json（平滑：新=0.7旧+0.3新观测）；
4. 回复用户：总胜负、最大偏差题、卡壳题、是否"提速但正确率存疑"（若有正确率录入）。简洁，三五行说清。

```jsonc
// data/profile/calibration.json
{"_default": 1.0, "math": {"choice": 1.1, "solve": 1.25}, "updated_at": "..."}
```

## 赛中 subagent 调速规则（有度）

允许赛中根据用户实际速度微调幽灵剩余配速，但硬边界：**全场累计调整幅度 ≤ ±10%，次数 ≤ 2 次**。**不做任何页面提示**（考场仿真：没人广播对手加速）——调整只静默写入 session 日志，供赛后复盘。超出边界 = 裁判作弊，绝不允许。

## 保护规程（数据仓 git——你只需要管这个）

`data/` 目录是独立的 git 仓库（代码仓归用户主 agent 管，与你无关，**你不许碰 data/ 以外的任何文件**）。规则：
- **改任何数据文件之前**：`git -C /var/minis/shared/paper-race/data add -A && git commit -m "before: <要做什么>"`
- **改完验证无误后**：再 commit 一次说明改了什么
- 比赛 session 落盘时桥会自动提交，不用你管
- 纯读操作（复盘、分析）不用提交
- 数据异常或改坏了：**不要自行修复，停手并在回复里向用户说明情况**（用户会找专人处理）
- sessions/ 只新增、不修改（补录类修正除外，需在提交信息里说明原因）、不删除

## 红线

- **只许动 data/ 里的文件**；app/、bridge/、docs/、design/ 都是代码仓，由用户的主 agent 维护，你一行都不许改
- 不删 sessions/ 历史数据
- 保持简洁：不要为了"功能完整"加用户没要的东西
